# RAG design notes

## Pipeline choices

The knowledge base has 17 fictional-company documents in two formats: 15 PDFs totaling 30 pages and two Markdown guides. The PDFs cover company facts, the service catalog, package inclusions, a rate card, materials and brands, process, timelines, warranty, payment, FAQs, lead qualification, and three customer case studies. The Markdown guides add operational details, city coverage, measurements, and a current decision register. The mix gives retrieval realistic variation in format and overlapping facts. Policy questions use the decision register as the current authority, while case-study prices remain historical. The ingestion layer reads PDF pages with layout preservation, reads DOCX paragraphs and tables, and retains Markdown/TXT table rows. It removes line-wrap and hyphenation noise without flattening headings or table sections.

Chunks are section-aware, up to 900 characters with 140 characters of overlap. That size usually keeps a short policy or FAQ answer with its context while limiting dilution from adjacent topics. Headings begin new retrieval units; table blocks stay intact when possible, so a rate row does not lose its column labels. The persistent Chroma index uses normalized `all-MiniLM-L6-v2` embeddings. Local embeddings keep the corpus on the machine and reduce API cost. For English plus Hinglish, this baseline is serviceable but not ideal; a multilingual embedding model is a clear next experiment.

At query time, Chroma retrieves a wider semantic candidate set and a lightweight lexical overlap score reranks it. Query-specific source boosts then prioritize the current rate card, warranty, payment, timeline, or decision-register authority where appropriate. This helps exact lookups and prevents historical case studies from outranking current policy. Cohere receives the retrieved excerpts through its structured documents API, and returned citation IDs are mapped back to source paths; unknown or missing citations are rejected. Deterministic paths handle package arithmetic, documented kitchen/wardrobe warranty terms, discount refusal, ambiguous pricing, and unsupported geography. Estimate output states area/rate assumptions and that the result is not a binding quote. The default chat model is Command R7B for lower-latency RAG; generation is capped at 300 tokens, and greetings/thanks use a local fast path.

Lead intent starts a conversational slot flow instead of a form. The consent prompt discloses up to 180 days of retention. The JSONL writer only saves after the customer provides name and contact and explicitly agrees to a team follow-up. Lead rows are Fernet-encrypted; writes fail closed without a valid `LEADS_ENCRYPTION_KEY`, and expired rows are pruned on app startup and before new writes. PII is redacted from chat history before it reaches Cohere. The assistant requires a minimum retrieval score, checks generated citations against retrieved filenames, caps prompts at 4,000 characters, and limits request rates per session and process. Public deployments still need edge access controls and multi-instance rate limiting.

Optional diagnostics are controlled by `DEBUG_LOGGING` (off by default). When enabled, each turn is appended to JSONL with a hashed conversation identifier, redacted user/assistant text, and retrieved source names, scores, and short redacted snippets. The configured debug log path is git-ignored. Operators should apply access controls and a retention policy before enabling logs in a shared environment.

## Testing status and known limitations

The Streamlit UI is branded BuildMate AI. It opens with an English greeting based on India-local time, has no language selector, automatically matches the customer language, and shows four rotating starter questions only after the first customer message. Clicking a suggestion submits it and replaces it with the next unused question. The repository includes six source-hit evaluation cases in `src/evaluate.py` and a nine-prompt demo run sheet. The unit and integration suite passes (`66 passed`): it covers estimate arithmetic, ambiguous pricing, discount refusals, PII redaction, encrypted lead persistence and retention, native citation mapping and validation, low-confidence abstention, English/Hindi/Hinglish response matching, fast greeting/model configuration, input/rate limits, deterministic package-rate answers, provider-error logging, deterministic bathroom-timeline and package-comparison replies, lead-flow FAQ continuity, secret-template validation, cleaning/chunking, Chroma ingestion/retrieval, stale-source reconciliation, UI scroll behavior, and opt-in redacted diagnostics. Chroma integration tests inject deterministic vectors, so they do not validate semantic embedding quality. The curated real-index evaluation passed all six source-hit cases (6/6) after building the local index. Streamlit's local health endpoint responds, and one live Cohere process answer returned mapped source citations. ## What I would improve next

Add an explicit evaluation corpus with expected answer facts, source recall, groundedness, and refusal checks; run it on a fixed model/version. Add a multilingual embedding comparison, hybrid BM25 retrieval, and a cross-encoder reranker if the added latency is acceptable. Improve PDF table extraction for scanned or unusually formatted files with OCR and table-aware parsers. Add lead deduplication, consent timestamp/source, deletion support, and a CRM integration. Store structured conversation/retrieval logs with PII minimization and deploy behind the company's authentication, edge-rate, privacy, and retention controls.
